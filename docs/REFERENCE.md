# rtpcr-java: reference manual

A Java port of the R package **rtpcr** 2.2.0 (qPCR analysis by the dCt and ddCt methods) together with its Shiny app. It has no external dependencies: JDK 17 or newer is all you need.

## Build and run
    ./build.sh            # Windows: build.bat   -> creates rtpcr.jar
    java -jar rtpcr.jar serve                 # web app at http://127.0.0.1:8080/
    java -jar rtpcr.jar serve --port 9000 --no-browser
    java -jar rtpcr.jar run ANOVA_DDCt --file data.csv --numFactors 2 --numRefGenes 3 --specs Concentration --block block --out result.csv

Functions for `run`: ImportQPCR, meanTech, ANOVA_DCt, ANOVA_DDCt, Efficiency, AbsQuant, TTEST_DDCt, WILCOX_DDCt. Option names are the ones used in the web form. For the four relative expression functions (ANOVA_DCt, ANOVA_DDCt, TTEST_DDCt, WILCOX_DDCt) `--techRep true` means that the data have a technical replicate column right after the biological replicate column: the technical replicates are averaged first (meanTech) and the analysis uses the means. In the web form this is the check box *Data have technical replicates*; there is no separate meanTech window.

## ImportQPCR: qPCR machine file to rtpcr CSV
Makes the input of the relative expression functions from the result file of a qPCR machine (Applied Biosystems / QuantStudio export, one row per well; the table is found by its `Sample Name`, `Target Name` and `CT` (or Cq / Cp) headers, any number of header lines before it and trailing lines after the first empty row are fine; UTF-8 or ISO-8859-1). The technical replicate clean-up follows [Auto-qPCR](https://github.com/neuroeddu/Auto-qPCR) (`archive_version_command_line/project/model_relative.py`, and its web version for *preserve*).

    java -jar rtpcr.jar run ImportQPCR --file machine.csv --refGenes ACTB,GAPDH --cutoff 0.3 --maxProp 0.5 --preserve false --repFromName false --splitPos 0 --splitDir first --dropCols Ct_GAPDH --out rtpcr_input.csv --qc replicate_QC.csv

In the web app it is the **Import machine data** button of the **Data** window (there is no separate ImportQPCR tab): the rtpcr CSV is added to the Data table and opened in ANOVA_DCt, ANOVA_DDCt, TTEST_DDCt or WILCOX_DDCt with **Open**. The replicate QC table (`--qc`) is written by the command line only.

| Setting | Meaning |
|---|---|
| Reference gene(s) (`refGenes`) | Required, comma separated, matched to `Target Name` without regard to case. They become the last E/Ct pairs; every other gene is a target gene. |
| CT-SD cut-off (`cutoff`, default 0.3) | The wells of one sample name and gene are technical replicates. If their Ct standard deviation (n - 1) is **above** the cut-off, the well furthest from the mean is removed, then the SD is recomputed, until it is at or below the cut-off or the maximum proportion is reached. |
| Max proportion (`maxProp`, default 0.5) | Maximum proportion of the wells of a group that may be removed; at most `floor(n * maxProp)` wells, and at least 2 wells always stay (0.5: 1 of 3 wells, 2 of 4). Wells removed before the limit was hit stay removed if the cut-off still is not reached (as in Auto-qPCR); such groups are listed in the warnings. |
| Preserve highly variable replicates (`preserve`) | A group above the cut-off keeps all its wells if |mean - median| / median of its Ct values is below 10 % (the test of Auto-qPCR). With Ct values around 15-35 this is nearly always true, so in practice this option switches the removal off. |
| Sample names end with a replicate number (`repFromName`) | `Ctrl_1`, `Ctrl_2`, `Treated 1` ... become Condition `Ctrl` / `Treated` and Rep 1, 2, ... (the last separator and number are split off). Off (default): every sample name is its own Condition with Rep 1, e.g. `AiW002-2-D0`. |
| Split direction (`splitDir`) and Split position (`splitPos`) | `splitPos` 0 (default): one `Condition` column. A number n >= 1 splits the condition name into two factor columns `Factor1` and `Factor2`. `splitDir first` (default, web: *From first*): the first n characters are `Factor1`, the rest is `Factor2` (`RD0` with 1 gives `R` and `D0`). `splitDir last` (*From last*): the last n characters are `Factor2`, the rest is `Factor1` (`AiW_D0` with 2 gives `AiW` and `D0`). A separator ` `, `_`, `.` or `-` at the split point is dropped. Every condition name must be longer than n and both parts must be non-empty, otherwise an error names the condition. Use the result with 2 factors in ANOVA_DCt / ANOVA_DDCt. |
| Remove columns (`dropCols`) | Comma separated names of output columns to remove, as they appear in the output and without regard to case: `Condition` (or `Factor1`, `Factor2`), `Rep`, `TechRep`, a gene name (its E column) and `Ct_gene` (its Ct column), e.g. `--dropCols TechRep,Ct_GAPDH`. Done last, after the split. A name that is not a column gives an error that lists the columns; removing every column is refused. The relative expression functions need the factor column(s), `Rep` and the E / Ct pair of every gene, so remove only columns you do not need there; the import message repeats this, and says not to tick *Data have technical replicates* if `TechRep` was removed. |

Only wells with Task `UNKNOWN` that are not omitted (`Omit` = TRUE) are used. `Undetermined` (no Ct) is written as `NA`. Efficiency E is written as 2 for every gene. The output has the columns `Condition` (or `Factor1`, `Factor2` with `splitPos`), `Rep`, `TechRep` (left out when no group has more than one well), then `gene`, `Ct_gene` pairs: targets in order of appearance, references last. Use it with *Data have technical replicates* ticked, 1 factor and the right number of reference genes. A gene with fewer wells than the other genes of a sample (e.g. after removing an outlier) is filled up with `NA`, which the technical replicate averaging ignores (but note that *Set missing Ct to 40* would turn such an NA of a target gene into 40). The QC table (`--qc`, command line only) gives for every sample and gene the Ct SD before and after the clean-up and the removed wells with their Ct. `examples/` has the sample machine file with its output. `verify/qpcr_import_check.py` runs the original Auto-qPCR function for comparison: the removed wells are identical, except for groups where `n * maxProp` ends in .5 (5 wells at 0.5): Python rounds 2.5 to 2 and removes 3 of 5 wells (60 %), ImportQPCR removes at most 2 so that the proportion is kept.

## Windows installer (MSI)
`make-installer.bat` builds `installer\rtpcr-2.2.0.msi`. The MSI includes its own Java runtime (jlink'd, about 40 MB), so the machines that install it need no JDK/JRE. Installing creates a Start-menu entry and a desktop shortcut for **rtpcr**; it is a per-user install (no admin rights needed) and a newer MSI upgrades an older one in place.

Starting rtpcr opens its own application window (no tabs, no address bar, own taskbar icon); closing the window quits the app. The window is rendered by the Microsoft Edge (WebView2/Chromium) that ships with Windows 10/11, or Google Chrome if Edge is missing; if neither exists it falls back to the default browser. Set `RTPCR_BROWSER` to a Chromium-based browser's exe path to force one. Settings of the window live in `%LOCALAPPDATA%\rtpcr`.

To build you need (build machine only): JDK 17+ and [WiX Toolset 3.x](https://github.com/wixtoolset/wix3/releases) on PATH, then run `make-installer.bat` (`make-installer.bat portable` makes an unpackaged app folder and needs no WiX). Without a Windows machine, push the project to GitHub and run the **Build Windows MSI** workflow (`.github/workflows/build-msi.yml`); the MSI is attached as a build artifact.

## AbsQuant (absolute quantification)
Input is a long-format CSV, one row per reaction: `Type` (Standard or Sample), `Gene`, `Copies` (known for standards, empty for samples), `Ct`, plus an optional group column (default `Sample`) and replicate column (default `Rep`). For every gene a line `Ct = slope * log10(Copies) + intercept` is fitted to its standards and each sample reaction is converted to copies, `10^((Ct - intercept) / slope)`; efficiency is `10^(-1/slope) - 1`. Results: standard curve table (slope, intercept, R2, efficiency, range), copy numbers per reaction, a summary per gene and group (mean, SD, SE, Lower, Upper) and the standard curve plot. Optionally a reference gene divides the target copies of the same group and replicate. Warnings are shown for efficiency outside 90-110 %, R2 below 0.98 and sample Ct values outside the standard range. The summaries can be drawn in plotFactor via the data sources *Output of AbsQuant (copies)* / *(normalised)*. Sample file: `data_absQuant.csv`.

## Efficiency check before running
When **Run** is pressed in the ANOVA_DCt, ANOVA_DDCt, TTEST_DDCt or WILCOX_DDCt window with an uploaded CSV, the efficiency (E) columns are checked: after the factor columns, the block column (if any) and the replicate column (plus the technical replicate column when *Data have technical replicates* is ticked) the columns form E/Ct pairs, and every E value must be between 1.3 and 2.3. If not, a pop-up says "Uncommon amplification efficiency value(s) in columns ..." (with the column numbers) and offers *Run anyway* or *Cancel*. plotFactor, Efficiency, sample data and earlier results are not checked.

## Editing the plotFactor plot
On the plotFactor "Plot" tab, the appearance controls (from "Letters vertical offset" down) sit above the plot in three columns and redraw it as you change them. Double-click on the plot: any text (titles, axis labels, legend, letters) to change its wording, size, color and bold; any bar or legend color to recolor that series (fill, opacity, outline); any line (grid, error bars, ticks, border) to change color, width and style for all lines of that kind. The toolbar has Undo, Reset edits, Save/Load style (JSON, reusable across plots) and quick show/hide toggles for grid, border, error bars and ticks. The axis lines (bottom, left) and the axis ticks are 1.5 pt wide by default, and the ticks always follow the width of the axis lines (change it with the axis lines' Width in the line dialog). **Major grid** is unchecked by default. Unchecking **Borders** removes only the top and right line of each subplot; the bottom and left lines stay as axis lines (they follow the border style until you edit them). Tick **Arrow heads on axis lines** to add an arrow head at the end of the bottom and left lines. **Legends** can be dragged with the mouse; right-click a legend and choose **Remove** to delete it (toolbar: *Restore legends*; with split panels every panel has its own legend). Click a facet label, a panel title or an x axis label to select all of them and drag to move them together (toolbar: *Reset label positions*). In the bar colour dialog, *Apply to all sub figures* applies fill, opacity and outline-width changes to the bars of every sub figure. In the text dialog, *Apply size, color and bold to all ...* applies the dialog's values to every text of that kind at once (e.g. all facet labels). Tick **Reference line at y =** to draw a horizontal line behind the bars in every panel at the y value you type in the box next to it (default 1; any number, including negative or decimal values); double-click it to change its color, width and style or to hide it (the y axis is extended to include the chosen value if needed). Double-click an x axis label to open *Text: x axis labels*, which has a **Rotation** slider/box (0 = horizontal to 90 = vertical, default 45) for all x labels; the plot layout adapts to the angle. Click an x axis label to select all of them and drag them together with the mouse. PNG, PDF and SVG downloads include the edits.

**Canvas space.** Under the plot, in the row with the Try! key, the four boxes **Canvas space above / below / left / right (in)** (default 0) enlarge the canvas around the figure. The figure itself keeps its size and position; the extra white space is there for added texts, moved labels and legends. PNG, PDF and SVG downloads have the larger canvas.

**Data points.** Tick **Show data points on columns** (plotFactor, controls above the plot; **Point size** next to it) to draw the replicate values the columns and error bars come from. It needs the data source *Output of ANOVA_DCt*, *ANOVA_DDCt*, *TTEST_DDCt* or *WILCOX_DDCt* and the Y column RE or log2FC. TTEST_DDCt / WILCOX_DDCt: each treated replicate is shown as its wDCt minus the calibrator mean (paired test: minus its partner), RE = 2^-ddCt (the Wilcoxon column itself is the Hodges-Lehmann estimate, the points are the raw replicates). **Hover over a point** to see its value (e.g. `RE = 0.5074`; shown in the plot window, not in downloaded files). **Double-click a point** to change the color, opacity, size and shape of all points, switch the black outline ring off, or hide them. By default the points are 6 pt (**Point size**), light grey inside (50 % opacity) and surrounded by a thin black circle (100 % opacity; the Opacity setting in the pop-up changes the grey inside only). ANOVA_DCt: each replicate is shown as 2^-wDCt (log2FC: -wDCt). ANOVA_DDCt: wDCt minus the mean wDCt of the calibrator level in the same gene and by-group, so the points scatter around the column (the calibrator column around 1). Points are spread sideways inside the column at random with a fixed seed (the picture does not change between redraws); letters, added text and comparison brackets are placed above the highest point, and the y axis is extended to include the points. Points in ANOVA_DDCt are raw replicates, so for unbalanced designs or specs that do not name every factor their mean can differ slightly from the model-based column.

**Compare columns (emmeans).** Tick **Compare columns** (plotFactor, controls above the plot; **Comparison p-value adjustment** next to it, default none) to compare the columns of every facet pairwise with emmeans. It needs the data source *Output of ANOVA_DCt* or *Output of ANOVA_DDCt*, because the comparison uses the model fitted for each gene. Calibrator columns are left out, and only columns of the same gene are compared (each gene has its own model). A column stands for the emmean of its factor combination (ANOVA_DCt) or for emmean minus the emmean of its calibrator in the same by-group (ANOVA_DDCt, i.e. exactly the plotted RE / log2FC), so a pair is compared by the difference of what the two bars show. For ANOVA_DCt the chosen display type replaces the letters of the *Letters Column* (its `sig` letters are plotted by default): the bracket types remove them, the letter types recompute them from the comparison. For ANOVA_DDCt the default asterisks (significance against the calibrator) are kept with the bracket types; the letter types replace them for the compared columns. Pairs with adjusted p < 0.05 get a bracket with `*` / `**` / `***` (p < 0.05 / 0.01 / 0.001); with the display type **Brackets (P-value)** the bracket carries the adjusted p-value itself instead (five decimals, `<0.00001` below that; double-click a p-value on the plot to change its Decimal No., size, colour or text). Brackets are stacked automatically (narrow ones lowest, each above everything beneath it) so lines and asterisks never cross; the y axis is extended to make room. Double-click a bracket line to restyle all brackets, or tick **Hide this bracket** in the same window to remove just that one (Undo / Reset edits bring it back). Drag a bracket with the mouse to move all brackets together (lines and asterisks); Shift + drag (or Alt, or "Drag labels one at a time") moves just that bracket. *Reset label positions* puts them back. Test: `java -cp rtpcr.jar verify/java/CompareTest.java out`.

**Rearranging facets and panels.** Tick **Rearrange facets / panels** (plotFactor, toolbar above the plot) and drag a facet (subplot) with the mouse onto another facet: the dragged facet takes the place of the one it is dropped on and the others move up or down. Hold **Shift** (or Alt) while dragging to move a whole panel of the split (4th factor) onto another panel instead; a drag that starts on a panel title or in the margin of a panel also moves the panel. While you drag, the facet or panel is outlined and the drop place is highlighted. The order applies to all panels, is kept when you change other settings and is used in the PNG, PDF and SVG downloads and in **Save style** / **Load style**; **Undo** takes the last move back and **Original facet / panel order** puts everything back in the order of appearance (it is also reset when you choose another facet or split column). Untick the box to edit labels, legends and bars with the mouse again. *Panels to draw* still chooses which panels are drawn; the dragging sets their order.

**Try! key (↻).** On the plotFactor "Plot" tab, the **Try!** key (below the plot) steps through every possible plot of the data. The factors are the columns before the ddCt (or dCt) column. Each press shows one factor layout with either RE (and Lower.se.RE / Upper.se.RE) or log2FC (and Lower.se.log2FC / Upper.se.log2FC); each layout is shown with RE first, then with log2FC. 1 factor: X axis only. 2 factors: every X/Group order, each with Facet = None, then Facet = the Group factor (4 layouts). 3 factors: every X/Group/Facet order (6 layouts). 4 factors: every X/Group/Facet/Split order (24 layouts). So the number of plots is the number of layouts x 2. The plots are shown in reverse order: the first press shows the last plot of that list, and the final press shows the first plot. A note under the **Run plotFactor** key reminds you of the Try! key. **Run plotFactor** draws the same plot as the first press of Try! (the data is loaded with those X / Group / Facet / Split / Y settings preselected). After the final plot it starts over. The **Undo** key (↺, a circular arrow in the reverse direction) to the right of Try! shows the plots that Try! generated before, one by one in backward order; Try! then carries on from the plot that is showing. In the plots the y axis title reads "Fold Change" for the RE column and "log2(Fold Change)" for the log2FC column (other columns keep their own names).


**Appearance.** The button in the top-right corner (sun icon) toggles between **Auto** (follows the system light/dark setting) and **Dark** (moon icon) with one click. The choice is remembered. The palettes are CSS variables in `style.css` (`[data-theme=...]`) and the toggle is `theme.js`; plots always keep their white background so they match the downloaded files.

## Data window (sample data)
The **Data** button in the top-right corner (left of **Theme**) opens a table of the files in the `samples` folder with their number of factors, target genes and reference genes, whether they have a Different Plates column, whether they have technical replicates (**TechnicalRep**: Yes when the file has a technical replicate column such as `TechRep` or `TechnicalRep`; you can set it yourself in the Edit row), and the doi of the paper they come from (a link). **Edit** changes that description (the data file itself is not changed). **+ Add data** adds a new CSV or TXT file (comma-, tab- or semicolon-delimited; a TXT file is saved as a comma-separated `.csv`): the file is copied to the samples folder and listed in the table; the number of factors, genes, the Different Plates (block) column and the TechnicalRep flag are suggested from the column names and can be corrected, and an existing file is never overwritten. Added files (not the ones that come with the program) can be deleted from their Edit row. In every row, choose a function (ANOVA_DCt, ANOVA_DDCt, Efficiency, AbsQuant, TTEST_DDCt, WILCOX_DDCt, plotFactor) and press **Open**: the file is loaded into that function as its input data, with the number of factors, the number of reference genes, the block column and the *Data have technical replicates* box (from TechnicalRep) already filled in.

**Import machine data** (next to **+ Add data**) makes the rtpcr CSV from the result file of a qPCR machine with ImportQPCR and adds it to the table in one step. Choose the machine file, a `.csv` or a tab-delimited `.txt` (the wells and the genes found in it are listed). Several files, e.g. one per plate or per gene, can be selected together and are merged into one table (wells of the same sample and gene on different plates become replicates; the well positions in the NA list get the file name in front), give the reference gene(s) and, if you like, the other ImportQPCR settings (CT-SD cut-off, max proportion, preserve, replicate numbers in the sample names, split of the Condition column, columns to remove; see the ImportQPCR section), a name for the new file and the doi, and press **Import**. The new CSV is saved in the samples folder like an added file; its number of factors, target genes and reference genes and its TechnicalRep value are taken from the result, and the CT-SD warnings are shown under the table. Open it in ANOVA_DCt, ANOVA_DDCt, TTEST_DDCt or WILCOX_DDCt from its row.

The files that come with the program are inside the jar and are read-only; what you add or edit is written to a real folder, which is shown at the bottom of the Data window: the folder given by `-Drtpcr.samples=...` (or the `RTPCR_SAMPLES` environment variable); otherwise `src/main/resources/samples` when the program is started from the project folder; otherwise `%LOCALAPPDATA%\rtpcr\samples` (`~/.rtpcr/samples` on Linux/macOS). The table is kept in `index.json` in that folder; a `.csv` simply copied into the folder is listed too. The bundled table (`src/main/resources/samples/index.json`) was filled from the column names of each file; please check the numbers, especially for the efficiency files (no factors) and the doi column, which is empty where the source is unknown.

## Differences from R you should know about
* Plots are drawn by a small ggplot2-style renderer, not by ggplot2. They follow the same layout rules (theme_bw look, hue palette, extended axis ticks, dodged bars, facets) but are not pixel-identical.
* The "further ggplot layers" text boxes of the Shiny app are not available (they need the R parser). The model object is downloaded as a text summary instead of `.rds`.
* Only the model features rtpcr uses are implemented: `lm`-type fixed models and random-intercept `(1 | g)` mixed models.
* ANOVA_DDCt ignores `p.adj` for the contrasts, exactly as the R code does (`adjust = "none"` is hard coded there).
* The printed tables in the package vignette come from an older package version; compare against the current code, not the vignette.

## Verification
No R was available when this was written, so results were checked against independent implementations (scipy, statsmodels) rather than against R itself: distributions, p-adjustment, Tukey, Shapiro-Wilk, t and Wilcoxon tests (p-values and Hodges-Lehmann estimates), lm-based ANOVA_DCt and ANOVA_DDCt (estimates, CIs, p-values), the repeated-measures mixed model (F, df, contrasts, p), and the efficiency slopes and slope comparison. Scripts are in `verify/`. Not independently checked: Wilcoxon asymptotic confidence intervals, Kenward-Roger versus Satterthwaite differences, Bonferroni/Sidak intervals on means, and exact R rounding corner cases. Please run your own dataset through R once and compare.
